# Server Manager i18n and Theme Design

## Goal

Add Vietnamese and English localization plus System, Light, and Dark appearance modes to the existing Server Manager without changing `env.json`, Docker Compose behavior, or the Nginx reload mechanism.

## Localization

- Support exactly two locales: Vietnamese (`vi`) and English (`en`).
- Add `server/manager/i18n.php` as the single translation dictionary and translation helper.
- Translate all user-facing Server Manager content, including headings, table columns, form labels, placeholders, buttons, confirmation prompts, empty states, validation errors, CRUD flash messages, command guidance, reload status, and fatal errors generated by the application.
- On the first visit, choose Vietnamese when the browser's `Accept-Language` starts with `vi`; otherwise choose English.
- Display a VI/EN language control in the page header.
- Changing the language submits a local request to Server Manager, stores the supported locale in the PHP session, and redirects back to the current page. Unsupported locale values fall back to the detected/default locale.
- Keep technical values such as paths, service names, container names, commands, domains, and PHP versions unchanged.

## Theme

- Display a theme selector in the page header with System, Light, and Dark options, translated in the active locale.
- Use CSS custom properties for all page colors.
- System mode follows `prefers-color-scheme` and reacts when the operating-system preference changes.
- Explicit Light or Dark selection overrides the operating-system preference.
- Store the selected theme in browser `localStorage`; no server state or cookie is required.
- Apply the stored theme in a small script in the document head before rendering the body to minimize a flash of the wrong theme.
- If browser storage is unavailable or contains an invalid value, fall back to System mode.

## Components and Data Flow

1. `i18n.php` resolves the active locale and provides translation lookup with optional placeholder interpolation.
2. `index.php` handles a language-change POST protected by the existing CSRF token, stores the locale in session, and redirects safely back to the manager page.
3. Server-side rendering uses translation keys for every user-facing string.
4. The browser-side theme controller reads and validates the stored theme, updates the document attribute, and listens for selector and system-theme changes.
5. Existing CRUD and reload actions continue to use their current data paths and behavior.

## Error Handling and Safety

- Translation lookup falls back to English when a key is absent in Vietnamese.
- Unknown language and theme values are ignored and replaced with safe defaults.
- Language switching remains protected by CSRF.
- Dynamic output continues to use HTML escaping.
- JavaScript translations are emitted with JSON encoding rather than string concatenation.
- No external assets, packages, analytics, Docker socket access, or network requests are added.

## Verification

No automated test files will be created, as requested. Verification will include:

- PHP syntax checks inside the Manager container.
- `docker compose config --quiet`.
- Manual HTTP checks for Vietnamese and English session switching.
- Manual browser checks for System, Light, and Dark modes.
- CRUD validation and reload-status rendering checks in both languages.
- `git diff --check`.

## Out of Scope

- Languages other than Vietnamese and English.
- Translating values stored in `env.json`.
- User accounts or database-backed preferences.
- Changes to Nginx, Supervisor, PHP profiles, or container orchestration.
